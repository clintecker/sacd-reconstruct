## 1. Connect: what made it work (Route A, decode-driven)

`gcpu-connect-path.md` (committed ed40006) found the blocker was **not** a
missing secure world: `i4CPSA_Inst_Connect` never issues an SMC. Its Create
step registers itself under `(0x16b, compid, 1)` and then queries a **peer**
under `(0x168, compid, 0)` — and no bdpdrv code registers type 0x168. The
fix is a 60-line helper module:

```
[CPSA_PEER] registered (0x168, 0xFFFFFFFF, 0) rc=0 fnslot=bf9253bc
[CPSA_PEER] op call: ctx=(null) type=0x16b compid=0
```

— loaded at smoke stage S06b, before the first INIT. The wildcard compid is
the matcher's own (`0x127908 cmn r12,#1`).

**The C106 oops that shaped the final module:** `i4CPSA_Inst_Destroy+0x12c`
(`0x54a54: blx r3` after `ldr r3,[r3,#4]`) calls the fnslot **table's second
entry un-checked** — the Im fnslot is a function table (`slot[0]` =
generator, called by Create; `slot[1]` = release, called by Destroy), not a
single pointer. A 1-word slot let `slot[1]` fall into zeroed `.bss` and
PC=0'd the guest the moment uninit first became reachable (i.e. the moment
Connect first succeeded). C107's module hands a 4-entry table of logged
no-ops. `i4ImReleaseInterface` itself NULL-checks its hook (`0x127974`) —
the oops was Destroy's own raw call, decoded instruction-by-instruction.

**Also new and proven: the second INIT succeeds** (`0x68000000` twice) — the
decode's A4 hazard (`-1` at Create `:883` on re-registration) did not fire in
this shape. Labelled MEASURED; the mechanism (why the busy check passed) is a
small OPEN.

## 2. The framing answer (C108)

The FE now serves the 2064-byte SACD channel instead of refusing it:
`0x5c404=4128 → 2064 bytes/sector` → per sector **12-byte zero header +
2048-byte fixture payload** (Level 0; the header's real semantics stay the
open question — zeros make the layout measurable without inventing fields).

The guest-side dump answers it:

```
MD5 name=sacd510 off=12  hash=e56de1add53c90dd30cf9232b29ddc93   <- LBA 510 oracle
MD5 name=sacd510 off=2076 hash=68e5b97be9a6db48a3d477d77522d47d  <- LBA 511 oracle
FRAMING layout=payload_at_12_stride_2064
PASS    framing verdict
```

— payload at offset 12 within each 2064-byte frame, stride 2064, both frames
byte-matching the ISO oracles re-derived host-side. The gate accepted the
hypothesis it was built to test, on real transferred bytes.

## 3. The idle-handshake rows (the -6 wedge, decode-driven)

`ata-window-a1a0-poll.md` decoded the C106-probe trace storm: the
`i4IdeHalSAtaReg -6 ST:0x58` branch reaches `vIdeHalForceArbiterIdle`, whose
poll reads `a+0x1fc` (12-bit TRP-FIFO fill, idle = 1) plus `a+0x1a0/1a4/1a8/
1ac` (whole-word `== 1`) with **no timer and no delay** — unmodelled, those
reads returned 0 forever at ~28 MB/s of `-D` trace. The model now serves the
idle handshake (`0xa1a0-0x1ac`, `0xa1fc` → 1; `0xa6b8` → 1; `0xa680` bit0
self-clearing; `0xa208` lossless RMW). C106b bisect note: the stub-bytes and
tar-bytes arms BOTH wedged — the knife-edge is real and the fix is the rows,
not byte-lottery.
