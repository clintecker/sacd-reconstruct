Date: 2026-11-08
Repo: `sacd-reconstruct` (standalone mirror; **no commit**)

## Goal
Make the HUD render with Sony’s real on-device screen font (TiresiasScreenfont 8.03) **without** requiring a separately-staged `sony-font.ttf` file to exist on the USB stick.

Constraints honored:
- **Renderer architecture unchanged**: no scene/layout refactor; only the glyph *source* selection/loading logic changed.
- **VERIFIED vs INFERRED** labels used.

## Baseline (how glyphs are sourced pre-change)

### HUD implementation path (VERIFIED, from source)
`tools/bx510_sacd_hud.c` already uses a vendored `stb_truetype` rasterizer.

Pre-change behavior:
- HUD takes `HUD_FONT` if set.
- Otherwise it defaulted to a *staged* carved font file (`/tmp/sony-font.ttf` on-device, `sony-font.ttf` in the simulator).

### Launcher dependency on `sony-font.ttf` (VERIFIED, from scripts)
The current on-device launcher stages a carved font file and hard-codes it as `HUD_FONT`:

- `evidence/bx510/hwmon-payload/hudlaunch.sh`:
  - copies stick payload `sony-font.ttf` to `/tmp/sony-font.ttf`
  - runs `HUD_POOL=1 HUD_FONT=/tmp/sony-font.ttf /tmp/sacd_hud ...`

- `tools/bx510_hud_repro.py` (guest repro) similarly stages `sony-font.ttf` into `/res/shim/sony-font.ttf` and runs `HUD_FONT=/res/shim/sony-font.ttf`.

Impact:
- If the staged font file is missing/mis-staged, the HUD falls back to the embedded 5×7 face.

## Implementation (what changed)

### Change summary (VERIFIED)
Edits are confined to `tools/bx510_sacd_hud.c`:

1. **`font_load()` now accepts Sony’s wrapped `/res/font.bin`** directly.
   - Detects the wrapper by checking for sfnt version `0x00010000` at offset `+0x0c`.
   - Uses the wrapper’s **big-endian** length field at `+0x08` if it fits, else falls back to `n-12`.
   - Copies the carved sfnt bytes into `g_ttf` and initializes `stb_truetype` from that buffer.

2. Added **`font_load_chain(preferred, &loaded)`**:
   - Try `preferred` (`HUD_FONT`), then fall back to stable defaults.
   - **On-device defaults**: `/res/font.bin` → `/tmp/sony-font.ttf`.
   - **HUD_SIM defaults**: `evidence/bx510/display-payload/sony-font.ttf` → `sony-font.ttf`.

3. Startup paths now call `font_load_chain()` instead of a single hard-coded default.

Net effect:
- Old launchers can keep setting `HUD_FONT=/tmp/sony-font.ttf`; if that file is absent, the HUD will still load from `/res/font.bin`.
- New deployments can omit `sony-font.ttf` entirely and rely on the shipped Sony asset.

### Typography / pixel size mapping (VERIFIED)
No draw-call changes were made. The HUD’s existing sizing logic remains:
- Canvas: `CW=640`, `CH=360` logical.
- Panel scale: `SCAL = panel_width / CW` (e.g. 1920/640 = 3 at 1080p).
- Text size is computed in **device pixels** from `visible_h`:
  - `g_body_px = visible_h/20` (clamped to >=18)
  - TTF logical pixel height: `lp = g_body_px / SCAL`

So at 1080p (typical):
- `SCAL=3`, `g_body_px≈54`, `lp≈18` logical; the TTF glyphs render at ~54 device pixels.

This keeps the scene/layout stable because all text placement already keys off these device-px-derived line heights.
